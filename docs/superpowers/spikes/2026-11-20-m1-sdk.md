## Working options config (Q1, Q2)

```python
ClaudeAgentOptions(
    cwd=<dir containing CLAUDE.md and .claude/skills/>,
    tools=["Skill"],                 # worked: no need for the disallowed_tools fallback
    skills=["hello"],
    setting_sources=["project"],
    mcp_servers={"spike": create_sdk_mcp_server(name="spike", tools=[add])},
    allowed_tools=["mcp__spike__add"],
    max_turns=6,
    model="claude-opus-5-5",
    cli_path=<explicit path>,
    env={"DISABLE_AUTOUPDATER": "1"},
    strict_mcp_config=True,          # see "Surprises" - required
)
```

Observed: `INIT tools: ['Skill', 'mcp__spike__add']` (no Bash/Read). `TOOL_USE mcp__spike__add {"a": 2, "b": 40}`, `CALLS [{'a': 2, 'b': 40}]`,
`TOOL_USE Skill {"skill": "hello"}`, answer contained "Xin chào từ skill hello" and "PAPAYA" (CLAUDE.md loaded), agent said it could not run `ls`.
The fallback (`disallowed_tools=[...]` without `tools`) was not needed, so `edit_options` (Task 21) should use `tools=["Skill"]`.

### Surprises later tasks must handle

1. **Account MCP connectors leak in.** Without `strict_mcp_config=True` the agent reported having "Gmail, Calendar and Drive" tools (claude.ai connectors from the logged-in account). With `strict_mcp_config=True` they are gone and only `add` + `Skill` remain. Always set it in `edit_options`.
2. **`INIT skills` lists more than `hello`.** Built-in/bundled skills (deep-research, design, dataviz, update-config, verify, debug, code-review, simplify, batch, loop, schedule, claude-api, run, ...) are listed in `skills` even with `skills=["hello"]`. They are skill names only; `tools=["Skill"]` still means no file/shell tools. Do not assert the skills list equals the project skills; assert `hello` is present.
3. **`cli_path` must always be passed.** With no `cli_path` and no bundled CLI, the SDK falls back to `shutil.which("claude")` and then `~/.local/bin/claude` etc. On this dev machine the PyInstaller probe without `SPIKE_CLI` silently succeeded using the user's own installed CLI. Real error only when no `claude` is found (see Q4).
4. `RateLimitEvent` messages arrive (status `allowed`, five_hour utilization 0.21); `overage_disabled_reason='org_level_disabled'`.
